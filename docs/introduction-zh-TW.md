# 一天多了千顆星，PaperOrchestra 怎麼把實驗日誌寫成論文初稿

實驗做完，結果散在幾份日誌裡。要把它們寫成論文，還得決定哪個發現先講、哪篇文獻該放在這裡，最後再把圖和內文排進投稿範本。Google Cloud AI Research 團隊把這段工作做成了一個開源專案，叫 PaperOrchestra。2026 年 11 月 18 日的 GitHub Trending 單日榜記錄了 1,072 顆新增星號。

它讓幾個 AI 代理分頭工作。有的讀研究構想和實驗紀錄、擬出大綱，有的找文獻、整理相關研究，寫作代理再接手各節。數據圖和概念圖也能放進稿子，最後輸出成套用目標會議範本的 LaTeX 檔。

我最想借用的是它處理零散筆記的方式。先有一份能修改的草稿，研究者就能把時間留給更需要自己判斷的地方。圖裡的差異怎麼解釋？那篇文獻真的支持這句話嗎？

# 稿證 PaperTrail TW 專案介紹

修稿時有個惱人的問題。一句話改了三次，意思已經和初稿不同，註腳卻還留在原處。要確認現在這句話站不站得住腳，往往得把原文再翻一遍。

我想把這道工序做得簡單一點。稿證會把研究筆記、讀過的文獻和資料表整理成繁體中文草稿，也把每一段用到的材料另存成表。在 Word 裡可以直接改頁下註，需要換版型時，也有 LaTeX 原始檔。

範例裡有一個值得回頭看的細節。加記頁碼或小節的那組，模擬回查時間平均較短，第 4 條引文卻剛好相反。打開證據表，就能找到那兩筆紀錄。這是我希望工具替作者留下的東西。
